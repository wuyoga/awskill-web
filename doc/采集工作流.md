# Skill 采集工作流

> 状态：已落地 JSON 草稿管线；CMS 导入后置。  
> 决策：自动化采集 + 人工只审结论字段。

## 目标

双通道采集 → 整理合并 → `content/drafts/*.draft.json`。  
CMS（Strapi）就绪后，再将 `draftStatus: ready_for_cms` 的草稿导入，不在本阶段接 CMS。

## 数据对齐

草稿中的 `skill` 字段对齐 `lib/data` 的 `Skill`，并额外保留：

| 扩展 | 用途 |
|------|------|
| `repositoryUrl` / `repositoryPath` | 源仓库定位 |
| `sources.github` / `sources.benchmark` | 原始采集快照 |
| `fieldMeta` | 每字段来源与置信度 |
| `review.pendingFields` | 必须人工审的结论字段 |

**结论字段（采集不得冒充已验证）**

- `compat`、`risk`、`riskSummary`、`permissions`、`status`
- `verifiedCommit`、`useCases`、`notFor`、`category`、`outputs`、`installs`

默认：`compat=未验证`，`risk=未评估`，`status=待验证`，权限全 `待评估`。

## 流水线

```
seeds/*.json
    │
    ├─► GitHub 通道     tools/skill-collect/src/sources/github.ts
    │                   仓库元数据、stars、license、最新 Commit、SKILL.md
    │
    └─► 对标站通道     tools/skill-collect/src/sources/benchmark.ts
                        - `skills-sh` → https://www.skills.sh/{owner}/{repo}/{skill}（公开页）
                        - `skillhey` → https://skillhey.com/skills/{slug}（公开页 + ld+json）
                        - `fixture` → 本地 fixtures（无网/测试）
                        注意：https://skill.sh 为待售域名，不是目录站；seed 误写 `skill-sh` 会告警并转到 skills.sh
            │
            ▼
         merge.ts      合并去重、写 fieldMeta、标 needs_review
            │
            ▼
   content/drafts/<id>.draft.json
            │
            ▼（人工）
   填结论字段 → draftStatus: ready_for_cms
            │
            ▼（后置）
         导入 Strapi 草稿
```

## 命令

```bash
# 可选：提高 GitHub API 限额
# set GITHUB_TOKEN=ghp_...

pnpm collect --seed tools/skill-collect/seeds/demo.json
pnpm collect --seed tools/skill-collect/seeds/demo.json --id frontend-design

# 每站新采 N 条；已写入 content/collect-state.json 的 ref 跳过（可断点续跑）
pnpm collect:batch --per-site 500
pnpm collect:batch --per-site 500 --sites skills-sh
pnpm collect:batch --per-site 500 --github   # 有 GITHUB_TOKEN 时也可自动开
# 重抓已采（补 Security Audits / installs 等）+ 同时再发现 N 条新的
pnpm collect:batch --sites skills-sh --refresh --per-site 500

# sitemap 未收录（noindex 合集页）可用 --refs 强制入队；默认跟进页内 /skills/{slug} 子链接（每页最多 40）
pnpm collect:batch --sites skillhey --refs handraw-style --per-site 200
pnpm collect:batch --sites skillhey --refs handraw-style --no-follow-links

# 合并草稿供本地 Next 静态目录使用（精选 Skill 优先保留，再追加采集 id）
pnpm merge:local
# → lib/data/skills.collected.json，由 lib/data/catalog.ts 合并导出
# merge 时自动做六维启发式清洗：分类 / Agent 声明 / 验证状态 / 安全 / 使用要求 / 输出格式
#（对标声明 → 部分支持+备注；不做「任务已实测」；风险带「待人工复核」说明）
```

## 对标站

| siteKey | 站点 | ref 格式 | 说明 |
|---------|------|----------|------|
| `skills-sh` | https://www.skills.sh | `owner/repo/skill` | 公开 HTML；采 `installs` / stars / First Seen / **Security Audits**（写入 `raw.securityAudits`，不作本站已验证结论）；官方 `/api/v1` 需 Vercel OIDC，本管线不依赖 |
| `skillhey` | https://skillhey.com | slug（如 `impeccable`） | 公开 HTML + Product ld+json；发现优先 sitemap，**noindex 合集页需 `--refs`**，采集后默认跟进页内子 slug |
| `fixture` | 本地 | fixture 文件名 | CI / 离线 |

seed 可用 `benchmarks: [{ siteKey, ref }, ...]` 同时采多个对标站。  
只读公开页；遵守 robots（两站均 Disallow `/api/`）。结论字段仍人工审，不直发。

## 与 PRD 关系

- 对应 M1「真实数据闭环」的前置：先有可导入草稿，再上 CMS。
- 不替代兼容性实测与安全评估。
- 安装量口径仍为 OQ-04，采集侧 `installs` 保持 0 / 待审。
